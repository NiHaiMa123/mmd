# 现成工具：MMD 换装这条路上已经有什么

> 这份笔记来自第五轮 review 后的方向性提问（"我是不是方向错了"），
> 目的是在继续自研之前，先确认社区里已经有的东西。

## 结论先说

**不推倒重来，但要把"贴合"这一环交给现成工具。**

- 手工/半自动的路线（PMXE）确实是 MMD 圈的真实做法，但它解决不了"一批衣服批量换到一个
  固定素体"。
- 现成的自动换装工具（下面 1）覆盖了自研流程里最大的一段。
- 自研工具链应该重新定位成：**批量编排 + 预检 + QA + 物理诊断**，而不是"贴合算法本身"。

## 1. PmxDressup —— 最该先试的

- 2023 年发布的 MMD 换装适配工具，Windows 发布包（BowlRoll 上的 1.00.03，2024-09）。
- 官方演示里列出的能力：指定来源服装与目标角色、**按骨骼长度自动适配体型**、
  **按身体厚度调整服装**、半透明显示目标身体便于检查、手动微调、选择输出材质、
  应用 Morph、**调整骨骼/刚体/Joint 关系**、复制或调整材质参数。
- **没有**确认到开源仓库或稳定的命令行接口（只能确认 Windows 发布包与交互式流程），
  所以它不能直接进批处理，但可以当**基线**：用它做一次刻晴→达妮娅的完整适配，
  看它能不能同时解决手粗 1.4 倍、腿比例、袜层贴图、鞋宽、物理刚体这五件事。
- 建议：这一步做完再决定自研算法还差什么。

## 2. Elastic Clothing Fit —— Blender 侧最直接的贴合工具

- 仓库：<https://github.com/VRC-Staples/Elastic-Clothing-Fit>（Blender 3.2+，含 5.x）。
- 算法：给衣服建代理 → 代理收缩包裹到身体 → 把位移传回衣服。
- 关键能力正好是自研缺的那几块：
  - **Exclusive Vertex Group Fit**：只拟合指定的顶点组，其余不动 → 鞋可以只放大鞋头，
    不动鞋跟/靴筒/金饰；
  - **Preserve Group**：排除某些组（腰头、领口），边界平滑过渡；
  - **Proximity Falloff**：离身体远的顶点少动或不動 → 裙摆不会被吸到腿上；
  - **UV Preservation**：保留来源 UV；
  - **Hull Fit**：用身体的凸包代理填掉腋下/裆部/大腿内侧的凹陷；
  - 代理是按网格算的，**不要求源和目标同拓扑** → 正好是"刻晴的鞋 → 达妮娅的脚"。
- 局限：它是通用 Blender 角色/服装工具，不处理 MMD 的骨骼、SDEF、刚体、Joint 和 PMX 导出。
  所以它能替掉的是 `project_layer_on_limb` 的几何部分，**替不掉**骨骼映射、权重迁移和物理迁移。
- 定位：**当作几何贴合的替代实现**，配套自己写的语义拆件（哪些顶点组该动）。

## 3. gret —— 径向基函数体型迁移

- 仓库：<https://github.com/greisane/gret>。
- `Mesh: Retarget` 用 RBF 做网格/骨架变换；作者列出的用途包括"把体型的 Shape Key 迁移到服装"、
  "在不同角色之间复用服装"。
- 限制：定义变形关系的源/目标网格必须**同拓扑同顶点序**。
- 但这给了一条比"逐骨轴径向投影"更稳的路：
  ```
  源 A 的身体
     ↓ 复制一份作为参考笼
  参考笼调整成 B 的体型
     ↓ gret RBF Retarget
  A 的衣服按同一个形变场变形
  ```
  一个共享形变场 > 很多条互不相干的骨轴投影，而且**更容易保住衣服的原设计**。
- 需要先建立可靠的 A→B 身体对应（这一步可以用上面的贴合工具做）。

## 4. blender_mmd_tools_append —— 原 MMD UuuNyaa Tools 的继任者

- 仓库：<https://github.com/MMD-Blender/blender_mmd_tools_append>，v4.x 支持 Blender 4.2–5.2。
- 提供 MMD↔Rigify 骨架整合、MMD 兼容骨架生成、骨骼命名标准化、材质调整与预设、
  **物理刚体转换**等。
- 自研流程里"骨骼命名/刚体相关"的部分，可能有一部分能直接用它的实现而不是自己写。

## 5. 物理侧：当 oracle 用的现成 runtime

- <https://noname0310.github.io/babylon-mmd/>：PMX/VMD 与 MMD 行为的专门实现，可脚本驱动。
  它也**不是官方 MMD 的完全等价实现**，但比在 Blender 的 `frame_change_post` 上重新创造
  MMD 的 IK/物理求值顺序更容易得到**可重复的外部对照**。
- 建议的顺序（REVIEW5 §8 的三级路线）：
  1. **先不动 solver**：把物理跑出来的骨骼轨迹录下来，之后关掉 Bullet 用保存的骨矩阵回放，
     让几何 QA 本身完全可重复。这一步成本最低、诊断价值最高。
  2. **再纠正关键 pair filter**：对 MMD 禁止而 Blender 共享层误允许的**近场**刚体对，
     用 Blender 的 Rigid Body Constraint / disable-collisions 处理，先用两球+裙摆短链验证
     它确实是"纯禁碰"（不加锁轴、不加弹簧、不破坏已有约束）。
  3. **最后才考虑**接一个现成 MMD runtime 做外部 oracle。
- 停止条件：在普通 QA、权重映射、坐标不变性和最小物理重放诊断稳定之前，不启动
  "自写完整 MMD 物理"的大工程。

## 6. 鞋：先确认是不是"设计预期的露趾"

REVIEW5 从 final24 的图里判断：紫色鞋面前端有开口，视觉上更像**开放式露趾鞋/凉鞋**，
而不是"鞋被撑破了"。

- 如果源鞋本来就是露趾的，那"露趾"就不是缺陷，只是目标脚更长导致露得更多。
- 验证方法：在相同的 heel–ball–toe 解剖坐标下，比较 A 的鞋和 B 的脚趾相对
  **鞋底前缘**与**鞋帮开口**的突出量，区分"设计内露出"和"多出来的露出"。
- 在这之前不要采用"封闭鞋局部隐藏全部脚趾"的方案——那会把设计内的露趾也抹掉。

## 7. 这一批的取舍

| 环节 | 继续自研 | 改用现成 |
|---|---|---|
| 骨骼映射 / 权重迁移 / 刚体迁移 | ✅ 保留（没有现成等价物） | |
| 几何贴合（漆皮层、鞋面） | | ✅ Elastic Clothing Fit / gret RBF |
| 整件换装（骨型+厚度+物理组） | | ✅ PmxDressup（先做一次当基线） |
| 批量编排 / 预检 / QA / 物理诊断 | ✅ 保留（自研的价值在这里） | |
| 物理 oracle | | ✅ babylon-mmd 之类（最后再考虑） |
