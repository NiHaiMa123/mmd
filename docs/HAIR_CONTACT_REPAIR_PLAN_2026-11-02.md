## 2. 本轮源码审查结论

### 2.1 已确认：浅穿越漏检

固定 PR47 的 `VirtualParticle.mesh_collide()` 先在半径内查询最近面，只有查询失败才射线回查，随后过滤背面接触。

已复现案例：半径 0.01m，历史点在表面外 0.025m，当前点在表面内 0.005m。最近面查询成功，跳过射线，再被背面过滤放行；预期应阻止本次入体，实际返回内部点。

这是明确的分支缺口。但单独把射线提前，并不自动解决已在内部的点、移动身体包住静止点，以及后续骨长约束回穿。也不能直接删除所有背面过滤，重新引入背面吸附或困住。

证据：[失败用例](evidence/hair_contact_20261102/pr47_function_boundary_probe.json)、[固定 PR47 源码][pr47-code]（`mesh_collide` 约 489–515 行）。

### 2.2 已确认：碰撞修正后仍有位置改写，末尾没有接触复查

`constrain()` 的实际顺序：

1. 角度约束；
2. `solve_collisions()`；
3. 骨长归位；
4. 部分粒子继续做反向约束及相邻混合；
5. 提交结果。

固定 PR47 的 599–610、616–639 行可直接核对。当前 length elasticity 为 1，骨长归位会实际执行。碰撞函数返回安全点，不保证本步最终点仍安全。

本轮用相同长度公式执行了一个独立数值反例：

- 身体为半径 1 的球，粒子半径 0.1；
- 父点 `p=(-2,0)`，碰撞刚修正的子点 `q=(0,1.1)`；
- 固定骨长为 2；
- 长度投影 `p + normalize(q-p) * 2` 得到 `(-0.24756818,0.96383750)`；
- 到球心距离约 `0.99512448 < 1`，重新进入实体。

它证明当前顺序缺少一般性的最终接触保证，**没有证明角色 f412 的唯一根因**。简单在末尾再推一次也可能破坏骨长，应在现有框架内协调接触与结构约束。

### 2.3 新核对：射线起点并非本次积分步的起点

调度为 `verlet_integrate → constrain → finish_step → apply_pose`。`finish_step()` 才执行：

~~~python
self.position_last = self.position
self.position = self.working_position
~~~

因此在本步碰撞时：

- `position` 是进入本步的已提交位置；
- `position_last` 是再前一步位置；
- 传给 `mesh_collide` 的 `pos` 已是当前候选。

PR47 用 `position_last → pos` 发射线，实际跨两个步区间，而不是当前步的 `position → pos`。这是源码时序结论；对真实角色的影响还需要阶段日志验证。函数 probe 手工填写“上一点”不会自动验证集成时序。

依据：[固定源码][pr47-code]（`mesh_collide`、`finish_step`、`jiggle_simulate`）。

### 2.4 已确认的能力边界：没有前后变形表面的相对扫掠

PR47 查询当前身体网格，没有利用前一时刻的变形表面计算相对穿越。当前身体由世界坐标 PC2 驱动，矩阵可以一直为单位矩阵，但表面顶点仍在移动。

“碰撞网格时钟与位置误差为 0”证明输入同步，不能证明算法检测了身体扫过粒子的过程。静止粒子被移动肩部包进去时，粒子自身射线可能很短。

此外，点射线的长度加上 radius 并不等价于扫掠球体或胶囊 CCD。骨段中部、擦边和宽发片接触依然可能漏掉。当前应先修已确认的骨点入体，之后再评估是否确实需要更完整的体积表示。

### 2.5 最坏帧连动态骨点也超限，优先解决骨链接触

[f412 骨点证据](evidence/hair_contact_20261102/pr47_worst_frame_contact_probe.json)显示：

| 骨点 | 埋入深度 | 原 PR47 静止查询推移 |
|---|---:|---:|
| Sidehair5.R tail | 5.76348cm | 0 |
| Sidehair6.R head | 5.76677cm | 0 |
| Sidehair6.R tail | 5.17994cm | 0 |
| Sidehair7.R head | 5.19460cm | 0 |

当前短侧发 1/2 固定，3–7 动态，不能用“都是固定骨无法动”解释下游深埋。真实发片顶点最大深度为 6.55679cm，面心最大为 6.56489cm。

静止查询设历史位置等于当前位置，只证明已在内部时没有救回；它不是完整积分器状态，不能还原最初进入过程。

### 2.6 需要正确解释的另外几件事

- 开碰撞后即使该步无真实投影，也会走不同的反向约束分支。作者 v4.1.0 将此列为正式功能；不能仅凭无接触运动与无碰撞版不逐值相同就判 bug，也不能新增逐值一致的验收门槛。[发布说明][jiggle-backprop]
- 当前 `probe_jiggle_pr47_mesh.py --boundary-only` 即使写出 `passed=false` 仍 `SystemExit(0)`。后续应修正退出语义，并要求执行器检查 JSON；只看进程 exit 0 不能宣称通过。
- `ClosedColliderField` 用闭合分量并集判断内外，但距离取全部原始三角面最近点。分量重叠时可能低估到并集实际外边界的深度；不能严格称为精确并集 SDF。这个边界不能消除已有 6.56cm 失败结论，也不要求立即启动复杂布尔重构。
- 背面过滤依赖法线朝向。当前路径应一次性核对实际碰撞面的法线与内外判断一致；历史其他候选做过重算法线，不等于当前源已核对。现阶段没有证据认定当前法线错误。
- 30Hz 改成 120Hz不是中性提高精度：当前插件的阻尼与弹性按步生效。保持认可基线，不把改变频率当成单独的精度开关。[时间与流程复核](HAIR_WORKFLOW_AUDIT_2026-11-02.md)

## 4. 执行阶段 A：补充观察，定位第一次入体

### 目标

使用固定原 PR47 和相同输入做一次有完整历史的诊断。A 阶段复现的是已知失败基线；取得原因证据后收束，不新增参数候选，也不用再渲染整段失败视频。

### 操作

1. 按现场交接核对认可版、本次输入、插件固定版本、身体/腕部 PC2 与后台任务；复用现有配置和验证入口。
2. 在 `scripts/bake_jiggle_root_point_dance.py` 的诊断路径补观察，或添加一个职责单一的 trace 包装器。尽量保持社区函数计算不变，记录任何插桩差异。
3. 全部 27 束从 f1 连续解算到 f450，保留 0.5 秒预运行和 30Hz。详细日志聚焦右短侧发，其他链保留原有轻量统计；不要直接从 f408 开始。
4. 查找第一次从外进入内的位置变化。初始发根附着和原始埋根要单独标识，不能把它们与自由动态段的新入体混为一谈。
5. 对首个相关事件记录命中面与前后表面状态；无需把全场每个面、每个阶段都写成大缓存。

建议最少记录：

| 类别 | 数据 |
|---|---|
| 身份 | 源帧/求解步、bone_name、particleType、parent 标识、static/enabled |
| 历史 | position、position_last、本次积分候选 |
| 各阶段 | 角度后、碰撞后、长度后、反向混合后、最终提交位置 |
| 接触 | 最近面/射线分支、命中面编号和法线、推移量、前后内外与深度 |
| 移动物体 | 相关接触面前后位置或等价可追溯表面数据 |
| 回写 | 对应实际骨骼 head/tail，与原始粒子的明确映射 |

现有 `motion.npz` 的 raw_particles 仅有位置、无逐粒子身份映射，不能直接当作完整状态恢复文件。

### 阶段产出

一份简短首入体报告，按证据区分：

- 碰撞函数直接放行；
- 碰撞已推出，后续约束拉回；
- 身体表面主动扫入；
- 粒子安全，骨骼回写或蒙皮显示才入体；
- 根区/固定长度导致局部不可行。

给出源帧、具体骨点、相邻阶段数据和正常角色关键帧。允许多个原因并存；不能仅凭最坏帧后验查询宣布唯一根因。

## 5. 执行阶段 B：最小维护补丁与有针对性的回归

### 修复范围

先修确定的浅穿越分支与时间状态问题，再依据 A 的实际证据补足内部恢复和约束后的接触处理。保持认可的动力参数、根部策略和 30Hz。

- 将“是否发生外→内穿越”与“当前半径内是否找到最近面”分开处理。
- 明确本次轨迹起点的时序，避免使用再前一步代替当前步起点。
- 为闭合身体内的自由动态点提供恢复路径，保留合理的原始根部附着语义。不能通过豁免整个 Sidehair 链或从评分中排除问题点取得通过。
- 若已证实长度/反向混合撤销接触，在现有框架内做有限的接触与结构约束协调，并检查最终残差；达到迭代边界仍不可行时明确报告。
- 同步考虑接触修正后的历史位置/速度，避免人工注入向外速度或把全部切向运动清零。
- 若移动表面是原因，说明使用了哪种相对运动或内部恢复方案，以及仍未覆盖的边界。不能将单条点射线宣称成完整 swept-sphere/mesh CCD。

不要同时更换重力、半径、固定区、步频和求解器版本。补丁写在可追溯独立副本/适配层，记录原始 commit、改动内容、补丁后哈希和开关；保留未改版本。

### 必要的小型回归

| 用例 | 要验证的行为 |
|---|---|
| 已有 cross_front_shallow | 半径内浅穿越仍被识别 |
| 外部静止、外部近面、内部向外退出 | 不新增外部吸附或阻止正常退出 |
| 已在闭合身体内的自由点 | 按新的内部恢复策略处理；不能沿用“内部点不动即通过”的旧期望 |
| 运动/变形表面扫过近乎静止粒子 | 区分对象刚性运动与实际顶点变形，验证实际实现覆盖的情况 |
| 第 2.2 节长度投影反例 | 检查最终状态，不只检查碰撞函数返回 |
| 正常发根附着 | 避免把原本合理的附着点强行推出而掀起整束 |

测试输出需要区分“旧实现行为记录”和“修复后的期望”。诊断失败用例本来用于暴露边界，不能用调整 expected 把失败改绿。反之，新增恢复策略后也不应继续把旧内部点不动的行为当成正确结果。

`--boundary-only` 的退出状态应与 JSON passed 一致；外层仍读取回执和日志，以兼容 Blender 异常不一定导致非零退出的情况。

### 何时停止扩大补丁

若需要自行搭建完整变形网格 CCD、自创通用约束求解器、重做整套蒙皮绑定，或新真实角色候选仍实际超限/失稳，停止该候选并报告。不要把“最小修复”扩展成另一轮无上限自研。

小型用例通过只表示边界回归通过，不构成完整角色通过，也不构成所有连续时刻零穿透证明。

## 6. 执行阶段 C：完整角色验证与同窗口交付

3. 评价对象仍是**真实显示头发顶点和面心**。骨点用于定位，不能代替最终显示网格验收。
4. 沿用最大深度 5cm 口径，报告最大值、源帧、发束、超限帧列表及与认可版的同口径对照。点数/范围可辅助定位，不变成新失败条件。
5. 先输出正常材质完整角色关键帧，检查是否明显飘起、突跳、拉伸；不能只交代理线条或局部单束演示。
6. 接触与观感检查均可用后，制作 7.5–15 秒完整预览，检查实际 24fps 输出时刻。源时间映射为 `(f-1)/30`，输出 i 对应 `226+(i-1)*1.25`；最终有非整数源帧，不能只用整数帧结果代替画面。
7. 音乐与原两帧偏移保持一致；180 帧、1920×1080、24fps、7.5 秒，核对新图像池、音画时长和完整解码。
8. 用户确认自然度后，再评估完整 15 秒和三分钟扩展。扩展需要覆盖完整输入/缓存与连续求解状态，不用 450 帧成功推断长片必然成功。

新候选一旦发现真实超限或明显失稳，按既有要求停止后续试跑和整段渲染，提交原因及证据。已完成的只读诊断可以收集整理，不默默启动其他参数组合。

建议每轮最小交付：

- 输入与插件来源、明确补丁差异；
- 首入体或失败原因报告；
- 完整角色深度汇总、身体动作保持结果；
- 正常材质关键帧；
- 达到门槛后的视频及解码回执。

不要为了这轮工作新增大型调度框架、无关 UI 或大批镜像实现测试。当前原 PR47 的 450 帧 Bake 回执约 42.37 秒，这只是该次仿真时间，不包含检测和渲染，也不是新方案性能承诺。

## 7. 替代后端：需要切换时按此顺序

### 7.1 优先候选：NovaBone Dynamics 1.3.0

作者[当前文档][novabone-docs]和[商品正文][novabone-product]已核对。2026-11-02 商品列出 `novabone-1.3.0.zip`，个人版 5 美元；部分搜索摘要停留在 1.1.0，应以实际包和文件清单为准。

作者文档提到内部点恢复、根部间隙过渡、接触后复查、混合后投影、骨骼回写和变形表面处理。这些机制与当前问题匹配；它们仍是**作者声明**，未在本角色上验证。

[公开仓库][novabone-repo]当前 main `5eb36596c1d356eb286fe79263806275d752859d` 仅包含文档和演示，未提供求解器源码。本轮没有购买或取得插件包，不能声称已审过其代码，也不能编造 `bpy.ops.novabone.*` API。

实际迁移顺序：

1. 检查本机是否已合法取得 1.3.0 或更新包；没有时明确说明包未就绪，不自动购买。
2. 取得包后先核实际版本、源码/API入口及 Blender 5.2 兼容；引用作者 UI 名称不等于已经具备后台命令。
3. 从相同未烘焙源工程建立原 27 束骨链，保留身体、腕部缓存、材质和镜头。先不运行会改静置骨向的 Fix Bones。
4. 以作者语义配置参数，不照抄 Jiggle 的同名 angle/friction 数值；自然度仍与认可版比较。
5. 代理体积仍不是原宽发片本身，继续用真实显示网格验收。合理根部豁免不能扩大为忽略问题发束。
6. 只做一个明确配置的同场景对照；实际失败后报告，避免扩展成大量后端/参数扫描。

作者还提供 Simulation Nodes（5.2+）模式作为骨链与官方 Hair Dynamics 的适配入口。是否能可靠后台建链和回写，以实际包验证为准。

### 7.2 免费后备：Blender 5.2 新 Geometry Nodes Hair Dynamics / XPBD

官方 5.2 新增 Hair/Cloth Dynamics，当前仍为实验功能；它与旧 Cloth modifier 是不同后端。官方文档提供变形网格接触、子步表面插值、发丝段与碰撞边的 Edge Contacts，以及接触/结构/速度统一求解。[官方介绍][blender-physics]、[XPBD 框架][blender-xpbd-simulation]

局限仍包括缺少自碰、单点对同一 collider 的接触数量限制，以及复杂凹面接触的精度/性能问题。不能宣称严格连续无穿透或直接可用三分钟。[求解器限制][blender-xpbd-solver]

接入可优先评估 NovaBone 的 Simulation Nodes 适配；不用该插件时，需要建立 Curves 与原发骨的可靠对应，并使用 Capture Rest Geometry、Hair Dynamics 和 Collider，正确开启 Deforming，按实际需要使用 Edge Contacts。集成成熟求解器可以接受，但仍需验证曲线到原显示发片的映射。

不要把旧原生 Cloth 的失败等同于已经测试过这套新后端；同样，不把工程里存在某个 XPBD 节点组当成完整接入成功。

### 7.3 暂不重开其他大分支

PPF/IPC、旧 Cloth、其他 Wiggle fork 可保留为历史和代码参考。当前问题已收敛到具体接触路径，不需要同时重开这些路线。更换插件的依据应是可核实能力和本角色对照，不能只凭名称、演示视频或“支持碰撞”的描述。
