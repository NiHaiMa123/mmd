# 换衣与 MMD 试做：问题记录与操作约束

## 2026-10-27：接触底座新增实测坑

- 真实角色原动作已互穿时，不能直接锁住错误的相对手姿态。先构造保留手指和掌向的接触目标，再回写肩肘腕，并核对真实蒙皮。
- 双手位置已正确，前臂仍可能穿胸。肘绕肩—手连线的极向是必要自由度；不能只改腕位置或把两手拆开。
- 三个真实关键姿态无交线，不代表过渡可行。本轮合法目标直接插值在 318–321 帧穿过手指阻挡；补引导仍会失败，需整段搜索和实际半帧复核。
- 几何图搜索可能选到手掌的另一侧而翻转手势层次。应约束最终相对位置和接触区域；限制“修正向量的符号”会过强，也不等同于层次保持。细节见 [真实 MMD 回写记录](MMD_GROUPED_CONTACT_2026-10-27.md)。

- Genesis 1.4.5 的 IPC 路径会在接触后再次做刚体积分；只重写输出文件或只恢复一次 q，仍可能暴露下一预测姿态而穿衣。限定拓扑下已改成预测在前、接触后恢复同一时刻 q 和速度、不二次积分；必须检查实际骨架而非只查原生代理。
- 原生场景 `geometries()` 是底层向量的视图。遍历时添加缝接几何会扩容、使视图失效；先用 `list(...)` 快照槽句柄，再添加约束。
- 随动衣料原生 SoftVertexStitch 保持距离，不等于保持完整偏移或夹紧法向。使用非零初始间隙，避免与启用的接触厚度矛盾；分别核验运动幅度和距离误差。
- 两手相对姿态保持且无交线，可能只是全组被锁住。新增共同位移检查与同目标无约束对照；早期位移过小候选未验收。
- 三角交线检测不能排除闭合体完全包含。六关节盒体回归额外使用完整 OBB 分离轴；不能把这套盒体内部检测直接等同于任意开口角色网格。
- 固定相对手姿态仅适用于声明的持续接触阶段，不适用进入／退出、滚动和整段舞蹈。六个平面关节与简化手块通过，不代表 MMD 多轴肩腕、手指和真实抱拳通过。见 [新增回归记录](CONTACT_LIVE_AND_BIMANUAL_2026-10-27.md)。

适用工程：刻晴服装／头、达妮娅素体、White Bridal 鞋。这里记录实际碰到的问题、原因与修复方法，供其他模型执行时复用。检查通过的范围必须随输出报告保存，不能从“脚本运行成功”推断模型正确。

## 文件、对象与来源

| 遇到的问题 | 原因与处理 |
| --- | --- |
| 同一画面出现数个角色、骨架挡住模型 | 输入、备份、碰撞体与交付模型同时可见。交付时只显示有效角色网格，帮助器隐藏；通过实际 Blender MCP 截图复查。隐藏渲染与隐藏视口是不同状态。 |
| 取景后角色小成一个点 | `view_selected` 对含空基础网格的程序对象不可靠，且启动脚本加载 UI 后会异步恢复旧视图。按求值后的身体坐标取范围，等 UI 完成加载再设置视图。 |
| MCP 返回的仍是旧工程 | 多个 Blender 实例共存时，默认 9876 端口可能属于旧实例。任何修改前先读取 `bpy.data.filepath`；新实例选用空闲端口并记录文件／端口关系。不能覆盖或关闭旧的未保存工程。本轮用窗口实际截图另行确认新工程。 |
| 输出文件名相同但实际结果不同 | 旧 `final/` 不一定是最近通过检查的版本。鞋应追溯 `checked/`，头使用 `proportions_v2/`；后续原生衣物结果另存。源资产不覆盖。 |
| 拿修好后的模型重新猜源顶点索引 | 穿鞋、换头、裁切后编号和高度均可能改变。保存来源 ID 与映射，不能只依靠顶点总数相同。 |
| 插件在开发目录可用，ZIP 安装却缺模块 | ZIP 必须带引擎代码；用独立解压目录加载，并检查界面注册及已有场景保留。当前专用配方不等于旧主界面的一键功能。 |

## 网格、材质和形态键

| 遇到的问题 | 原因与处理 |
| --- | --- |
| 首个表情变成模型基础形状 | 提取网格时先创建正确 Basis，再复制其他形态键及 relative_key；保留权重、UV 和材质角色。 |
| 复制后丝袜出现交替三角高光 | 丢失模型作者提供的角法线。复制角法线，容忍 Blender 法线重新打包造成的约 5e-5 数值误差。 |
| 用 `mmd_` 组占了四骨权重名额 | `mmd_vertex_order`、`mmd_edge_scale` 是辅助元数据。保留它们，但仅实际变形骨参与四骨截取和归一。 |
| BMesh 拓扑操作后来源 ID 丢失 | 临时顶点对象引用不是可靠持久键。用整数层保存 ID，再核对坐标；曾导致足部来源从 4,968 个误剩 3,824 个。 |
| 材质被全部误判为透明 | Blender 5.x 的 `DITHERED`/旧 `HASHED` 并不代表模型本身透明。应检查实际混合方式及 alpha/纹理，不能按名称推断。 |
| 碰撞计数落在错误面上 | BVH 返回筛选后三角面列表的序号，不是全网格面号；保留筛选映射。几何节点生成后也不能沿用原基础网格的顶点编号。 |
| 节点属性查不到或落到 `.001` | 顶点组也占属性名。审计字段单独命名；求值前先给所有上游对象写齐审计字段，再求值下游节点。 |
| 最近点吸到了错误部位 | A 字站姿手在臀侧，全局最近面可能是裙褶或臀。手、脚、上臂等分别建立候选区域；骨名也不能单独判定部件。 |

## 鞋、脚与头

| 遇到的问题 | 原因与处理 |
| --- | --- |
| 高跟鞋被拉瘪、扭曲 | 硬鞋不能与软衣服共用整体投影变形。保留硬鞋形状，调整鞋内脚形、绑定和接触；不要删脚或拿空鞋掩盖问题。 |
| 画面正面正常，内侧／鞋跟仍穿模 | 需要每脚多方向检查，并计算完整脚、袜层与鞋各部件交线。鞋外轮廓和接地高度通过不能替代鞋内检查。 |
| 重做丝袜破坏了已修好的脚 | 必须从足袜补片建立前的输入追溯索引，直接保留 4,968 个足袜点的坐标、权重和全部形态键。不能在新 `Stockings` 上套用旧 `Cloth` 尾部索引规则。 |
| 换头后脖子显短、头显小 | 不能只按脸宽匹配。对照完整头部和肩颈比例；当前基线为刻晴头原尺寸的 0.94、上移 18 mm。 |
| 领口遮住接缝就算换头完成 | 实际需颈口裁切／桥接、皮肤过渡、眼骨引用、原生表情和头发物理；源骨内部 ID 不可直接复制到目标。 |

## 丝袜与多余片面

| 遇到的问题 | 原因与处理 |
| --- | --- |
| 臀部丝袜仍按刻晴体型，达妮娅臀部穿出 | 旧腿骨筛选没有覆盖臀胯。新袜层取目标身体变形后的外表面；不靠新增删除身体掩盖穿模。 |
| 接缝波浪、内部细节也变成丝袜 | PMX 皮肤在 UV 接缝处断开，且含不属于衣服的内部小岛。先焊合外层接缝再求法线，并排除内部表面。脚部例外，不破坏足袜接缝的精确坐标。 |
| 两腿间出现大面积片状物 | 旧版补裆边界用通用填洞形成横跨空隙的大面；运行时又叠加了内部表面的袜层。2026-10-26 按用户反馈断开补裆分支，并从袜层屏蔽 6,164 个内部来源面；身体坐标和形态键保留。旧的臀部视线检查没有发现被裙子遮住的这一处，需要专门低角度近景。 |
| 旧金属腿层与新丝袜重叠 | 除移除旧袜外还须检查独立覆盖层；已移除 902 个残留腿部金属面，金纹改用独立纹理遮罩。 |
| “黑丝”实际像漆皮或出现摩尔纹 | 应用视角密度变化、克制高光与非周期细噪声；波纹节点容易产生摩尔纹。当前仍为不透明仿透肤材质，不能声称等同参考图的真实透射效果。 |

## 袖子、饰件与物理

| 遇到的问题 | 原因与处理 |
| --- | --- |
| 宽袖向后展、默认形态错 | 来源袖链的休息形态不能当垂坠效果。重力试算后，同时更新袖子、形态键、骨、刚体和关节的定位。 |
| 小金属饰件或流苏飞离 | 仅处理大连通岛会漏掉小部件；曾漏 824 个小饰件点。处理所有相关骨驱动点；换成网格布料后，饰件也必须跟随布料代理，不能只按离主面 19 mm 以内筛选。 |
| 把整条宽袖压塌到手臂 | 挂在上臂上的宽袖仍可能由袖链主导。不能仅求上臂权重和就判为贴身；固定区和自由下摆要分开。 |
| 弯肘袖口露肤 | 留肘部空间、固定区重新采样目标权重；前臂跟随碰撞、局部间隙和有厚度内衬可减少露肤。内衬主体通过不代表外层宽袖全部交叠已解决。 |
| 皮肤接触修正乱拉远处下摆 | 限制到近距离影响带，避免宽松区域被最近面投影吸回身体。 |
| 原始交线计数与可见露肤不一致 | 内部交线和外部视线覆盖分别报告；alpha 孔洞也需考虑。不能为得到 0 任意缩小审计区域、删皮肤或忽略失败样本。 |
| 刚体碰撞组全错 | mmd_tools 的 mask=True 表示排除，与原 PMX 位含义相反；Blender 碰撞层也不能编码任意成对排除。用完整成对约束并核查矩阵。 |
| 物理看似运行，所有帧实际是休息形状 | 从原对象而非 evaluated 对象取网格。必须取依赖图求值结果；借用网格需在有效期内复制或读完后 clear，不能跨依赖图更新保留失效引用。 |
| 从模拟后的骨骼烘焙“跟随”轨迹 | 会把物理反馈混进碰撞体输入。先捕获仅动画的运动学轨迹，再建立物理。模态 2 只跟旋转，不可随意替换成完整变换。 |
| 网格布料和 MMD 袖链同时驱动 | 会重复施力或重复变形。本次网格试验不用袖／裙刚体驱动；头发等其他次级物理暂不纳入试验。 |
| 一件衣服的两张重合材质面互相撞炸 | 纹理／金属覆盖层共享形状，但不应分别当物理布料。每层只解算一次，视觉覆盖层跟随同一代理；不同真实裙层仍分别保留。 |
| 下裙片整片掉到地上 | 独立下层裙片顶端低于主裙固定区，实际没有固定点。每个物理连通岛单独设固定边并检查固定点数，不能只检查整物体有 pin 组。 |
| 15 秒试片衣服塌皱，硬调刚度仍被拉扯 | 新 Cloth 层释放了成型裙片；高度阈值生成的 Pin 还继承旧骨权重。一条全固定边两端分别跟上半身与旧裙骨，基础 22.34 mm 在第 270 帧变成 52.09 mm。先整理结构分区、锚点和权重，再调柔软度。三组对照及 B 站出处见 [起皱研究](CLOTHING_WRINKLE_RESEARCH_2026-10-26.md)。 |
| 近似固定点被算成完全固定点 | Pin>0.999 仍可能是软过渡。检查刚性附着误差时区分 Pin 精确为 1 的点；保形修复抽查 32 条真正固定边，长度误差低于 0.002 mm。详见 [实际修复](STRUCTURED_CLOTH_REPAIR_2026-10-27.md)。 |
| 使用负帧预热后缓存记录不完整 | 改用正帧 1–46 预热，人物、镜头、表情一并偏移，可见区间 47–496；音轨随可见开头对齐。必须重开工程验证缓存，不能只检查第一次连续播放。 |
| 拉伸“9 倍”被误读成相对原网格 | 旧报告以第一舞蹈帧为参考，该边当时已被压至 5.75 mm。原始基础边为 22.34 mm，问题帧 52.09 mm；需明确参考姿态，并列基础和求值长度。 |

## 动作、音画与验收

胸口修复补充（2026-10-27）：

- 团皱可能在适配后的基础网格中已经存在；先对照中立姿态、灰材质和原衣服，再决定是改版型、权重还是布料参数。胸衣不应随裙摆一起释放为自由布料。
- 同材质也会复用 UV：只取最近 UV 顶点／第一张三角面可能对应到其他衣片；细分顶点须做三角面插值，重合候选须结合空间与连通关系判断。
- 包围盒选区会混入上臂饰件；应结合原始骨权重及源坐标。白色胸衣曾误含 11 个布料近邻点，本轮从传递选择中移除。
- 身体权重直接最近面传递到成型胸衣，可能从上臂／肩部吸到权重；抬手时胸口会出现尖角。领口与下胸应分别约束影响骨。
- `set(arm.data.bones)` 包含 Bone 对象，并非名称字符串；名称过滤应使用 `.keys()`，否则权重传递会悄悄得到 0。恢复报告必须记录命中数与实际改写点数。
- 背面饰片不能沿正面射线推到身体前方；需先分正背区域。几何与自定义法线分别验收，灰材质也可能保留错误法线，不能替代几何面法线折角计算。
- 1080p 必须从原始场景重新渲染并查 PNG 尺寸；改变编码器输出尺寸只是放大。逐帧图像编码需设置正确输入帧率，避免 PNG 默认时基造成重复／丢帧。
- 棕色小块未必是皮肤：本轮以像素射线和原始面索引追到腰带内层，身体位于衣片后 17–19 mm。最近面射线须同时区分各层衣片，不能为此削身体。边界混合和身体间隙探针无效，未应用；腰带层间小交叠仍记录为待细修。

## 衣服／身体穿模复查补充（2026-10-27）

- 整面归同一骨权重区域才计入皮肤，会漏掉肩肘等混合边界。服装审计应先按实际皮肤材质收集所有求值三角面，再加区域标签；不明区域也必须参与碰撞。
- 一整片衣料埋在身体里时可以没有交线。内衬不能仅靠交线为零验收，须检查内部点和外形。
- 动作改动后按三个附着骨搬运旧绝对坐标缓存，仍可能拉成长条。应核查服装所有附着和层次并重新计算，不能用“缓存文件能读”证明兼容。
- 衣服逐点推到最近身体面，即使数值改善也会把袖口、背片、饰件压碎。须限制形变、保护结构，并独立查看正侧背及纹理；最大位移和交叉数都不能单独证明通过。
- 保守体素外壳需要做源皮肤包含、真实交叉和拓扑检查；本轮代理还存在非流形连接，不能仅凭没有皮肤交线称完整闭合实体已验证。
- 由皮肤重建丝袜可能把身体穿模换成鞋袜穿模。本轮新袜对身体为零，但对鞋有 16,820 对交叉，已拒绝。脚、袜、鞋必须一起验收。
- 新贴身层按顶点独立选源衣片可能跨材质／UV 图集；按面统一来源也不足以解决本轮映射与覆盖错误。不能把这类外观破坏的新网格交付为贴身层修复。

本轮没有新的通过验收的服装版本，详见 [服装／身体接触记录](OUTFIT_BODY_CONTACT_2026-10-27.md)。

动态接触补充（2026-10-27）：

- Genesis＋libuipc 小样实测发现：普通 FEM 固定点接口拒绝 IPC；需在原生初始化前接固定点，不能把 API 调用被拒绝当作固定成功。
- 当前版本组合的直接转动关节出现原生代理与目标骨架旋转方向相反；必须先用无负载动作核对轴方向，再测试接触，不能只看到关节数值改变就称反馈正确。
- `two_way_coupling=False` 不代表所有耦合模式都关闭反馈；直接关节模式仍回写关节状态。对照实验须按具体路径设置。
- 原生 ABD 场景实例的变换可能不是要导出的实时状态。应使用状态访问器，并让骨骼和布料取同一时刻；本轮原始实时骨架仍拒绝，只验证了保持枢轴／骨长的单关节物理输出。详情见 [底座实测](CONTACT_BACKEND_PROBE_2026-10-27.md)。

- 用户已否决几何采样通过版的抱拳。应区分有意接触和意外碰撞，保留双手接触区、相对掌向和交叉顺序；不能把手分开以后以“交线为零”验收通过。保持单手世界朝向也不等于保持双手手势。
- 普通扫碰可用相对法向速度约束并保留切向运动，但须经完整骨链 IK、时间平滑和连续碰撞复验；不能将已穿透后的最近面逐帧推离冒充沿外表面滑行。
- 头／躯干优先保持的是原动画轨迹；两肢修正也要考虑支撑脚、持物及有意接触，不能无条件各退一半。衣料接触还需摩擦、弹性与惯性，不能只看顶点间距。

- 关键帧和整数帧均无交线，不代表插值期间没有穿过。本轮半帧复查发现两个残留点，增加分数帧修正后再对困难片段按八分之一帧核对。仍不能把离散采样当连续碰撞证明。
- 衣料的规定运动碰撞体不会因受力而修改骨骼。要让衣服挤不下时改动作，需要外层动作优化与内层衣料接触反复验证，不能只换布料求解器。
- PPF Windows 原生便携运行已实测；动画碰撞体要按当前前端的静态运动协议配置。照搬另一版解码器的零材料值会被拒绝，随意改成极小正值也曾导致 Hessian 数值失败；按本版有效参数核验。
- `scene checks: clean` 后仍可能抛出初始交叉异常；必须读最终状态。当前全层版有严格失败记录，不能打开 `allow_intersection` 或忽略接触对来把失败改写成成功。
- 衣料根部硬固定会造成局部不适定；改软附着能释放位置，但会产生跟随误差。本轮约 42 mm 的偏差未出现接触阻塞信号，不能仅凭误差阈值认定“空间不够，改动作”。
- 新旧参考采样率可能不同：含半帧与分数帧关键点的动作参考，应按时间插值到求解器缓存时刻，不能直接用输出帧下标索引输入数组；越界应失败。
- 原衣服 UV 缝处存在重复顶点，焊接只用于物理代理并保留回写映射。代理清理还要约束全轨迹最大位移，单边很短不代表传递合并后的整簇偏移仍小。
- 静态碰撞体内部大量重叠会使全局候选配对耗尽内存；有界 broadphase 应保留全部衣料相关接触。跳过规定静态体互碰不代表胸衣、饰件等已经通过互碰验收。
- Blender 默认可能在 Python 异常后仍返回进程成功；后台验证加 `--python-exit-code 1`，并核对报告及产物。受限启动无输出时，不应写成测试通过。
- 60 个缓存样本若含 46 帧预热，实际舞蹈不到半秒；数值低模预览与完整高精服装、15 秒全段、原生 PMX 动力学必须分别报告。
- 径向或最近面逐点推离不能保证整张衣片不穿透：连点的三角面仍可能切入身体，也可能改变双层衣片层序。本轮裙片外推候选产生更多交叉，已拒绝。远处的袖子、饰片也不能当成人体外包络。
- `np.load` 读取 NPZ 返回惰性归档；在逐面／逐顶点循环反复访问同一数组会反复解压。本轮输入诊断改为需要的数组一次读取，避免把大量时间耗在重复解压上。

- 身体自碰撞、衣料接触、空间不足后的动作反馈是三个不同环节。只加 Shrinkwrap、增大厚度或删皮肤，不能实现骨骼避碰。
- 可见手部不一定在 Body 中；当前手套和手部网格位于 `Cloth`，仅检查素体会漏掉约 7900 个手部顶点。
- 顶点组 `mmd_edge_scale` 的权重不能参与“主导蒙皮骨”统计，否则整个模型会被错误归入同一组。
- 按身体部位裁切的网格带开口，最近面法线的负号不能独自证明点在实体内。应结合三角面交叉并处理肩部切口误报。
- 检测和优化要把四边面明确三角化；目标面索引、重心权重、雅可比和实际网格须一致。
- `hide_viewport=True` 会禁用物体的求值；对这样的辅助对象调用 `evaluated_get` 可能读到未变形的基础网格。用于导出的蒙皮参考应保持参与求值，使用 `hide_set(True)` 隐藏显示；必须核验不同姿态的坐标确实变化。
- 最近面间隙、BVH 候选和真实面交叉须分开；边缘擦碰不应等同于穿入。新审计额外检查非共面交线长度，容差为 20 微米。
- 整数帧全清也会漏掉半帧穿插；第一版时间平滑候选在 899 个采样中仍有 2 个半帧交叉，不能宣称全程无穿透。
- 单纯允许手腕自由旋转可让数字通过却破坏手势。难帧中主要冲突是双手互穿；需移动手的目标位置并让肘部调整，不能仅扭开手掌。只给双手相同平移也不能解决它们的互相穿入。
- 烘焙四元数关键帧需保持相邻半球一致；不能依靠逐分量线性插值自动避开相反符号。
- 新 Action 若只复制却不设置 fake user，原 Action 可能在保存重开后丢失。保留原动作时必须验证重载。
- 逐帧热启动会在误报约束下放大姿态漂移。保留冷启动回退、总角度限制及真实交叉验收；不能把残差减少等同于解算完成。
- 动作改变后，隐藏旧缓存对象并不会阻止其他几何节点读取旧缓存。应使旧缓存及引用它的绝对位置驱动明确失效，再生成新缓存。
- 衣料起始自交不能指望稳健 CCD 求解器自动接受；应先整理服装初始层次和接缝。官方 PPF 实测的失败、研究来源及范围见 [动态接触记录](DYNAMIC_CONTACT_RESEARCH_2026-10-27.md)。

13 秒袖子问题补充（2026-10-27）：

- 仅看边长最大值会漏掉保形混合中的压缩；应同时检查边长最小值、低分位面积和连续帧。旧版右袖在 13 秒的边长最低只剩约 11.7%，12–14 秒内还有更低值。
- 相反朝向直接混合坐标会抵消宽度；改为旋转对齐后混合局部形变，并加入接缝、长度、面积和时间约束。成品是实际 CLOTH 加约束后处理，应如实标明。
- UV 接缝的重复顶点会进入物理代理。每袖发现 11 对重合边界点；重建原生缝合解算的候选仍有问题，最终在输出约束层缝合，不能声称原解算网格已经完成缝合验收。
- 外推重心系数曾达到约 6.55，放大局部变形；袖饰采用 0–1 系数和刚性局部偏移。
- 几何正常也可能逐帧跳飞：从恒等四元数各帧单独选最短弧，在 180° 分支处会换方向。最终保持半球与角度连续，并加入跨 180° 回归测试。
- 加刚度、减质量或叠加裙摆碰撞并非通用修复，需逐段对照；本轮这些候选未采用。最终结果及局限见 [13 秒袖子修复](SLEEVE_13S_REPAIR_2026-10-27.md)。

多发束与固定发根补充（2026-10-29）：

- 第二束点缓存复用同一选择属性，会静默改写第一束的选择。每次创建独立属性，绑定前拒绝顶点重叠，并以保存重开、子帧和双缓存组合测试验收。
- 左侧发束在第 1 帧已经有 19 组皮肤交线。先保留 114 个固定根合法化初态，最大修正约 7.37mm，不能把这一步归作动态碰撞修复；原始休止坐标仍用于量测应变。
- 固定发根被手掌／前臂实际穿过时，软发束无处可退。原生左发束解算在第 245 帧发根漂移约 11.04mm，不能用提高根部刚度或增加子步掩盖空间冲突。
- 保守胶囊覆盖根点不代表精确覆盖根表面，也可能挡住空隙。固定点有符号距离、真实根部三角形交线与包络间隙分别记录。
- 整数帧路线可行不代表插值可行。左臂候选整数帧通过，四分之一帧第 243.5 帧仍穿头，且出现约 90mm/帧的修正跳变；该路线没有直接采用。
- 手腕目标略超固定骨长时可以投影到可达球壳；不能因此拉长骨骼或把实际被截断的位移当成已达到目标。
- 单方向平移与原动作附近的局部接触优化都可能失败。用规划路线作初值、加入受限腕转与时间约束，是需要独立验收的求解分支；交线、固定根失败和动作自然度不能互相抵消。
- 上述 114 个点是导向几何启发式选取，并非全部真正硬附着点。核对原权重后，只有 36 个点完全绑定头骨，其余为过渡区；真实硬点仍在第 242 帧穿入约 7.5mm。保留全部真实硬点后，25mm 手臂绕行通过 97 个 1/16 帧样本，最小实际间隙 8.82mm。不能仅通过减少固定点取得通过，柔性过渡区和全部发面仍需重新解算、检查应变。

有限宽度物理代理补充（2026-10-29）：

- 显示头发即使焊接接缝，仍可能含大量有意重叠发片。先检查非邻接初始自交，不能把显示网格直接当合法自碰撞物理壳。
- 碰撞距离设置后必须读取实际 RNA 值。本机 Cloth 的 0.001 单位下限会静默截断较小设置，对亚毫米短边造成不合理排斥；独立缩放仿真坐标后还要验证碰撞体逐姿态与原皮肤一致。
- 整数帧物理稳定不表示直接子帧求值稳定。原生 bake 也要实际复测；本轮需要先将代理转为随动局部缓存，再驱动显示变形。重开、八分之一帧和原发根误差均要独立核对。
- 物理代理无穿模不能替代显示发片检查，蒙皮混合权重也不等同于物理固定权重。只释放非硬根的试验仍可能拉伸；内部结构支撑也必须验收，不能根据“更像体积”直接采用。
- 接触投影消除交线后仍可能把发片拉长。本轮顺序投影 41 个采样交线为零，但最长边达到原长 1.3143 倍，仍拒绝。记录见 [有限宽度物理代理](SURFACE_PROXY_HAIR_2026-10-29.md)。
# 2026-10-30：动作反馈、关节蒙皮及物理体积

- 本机受限命令环境与提权宿主的进程视图不同。默认 Get-Process 查不到后台程序不等于宿主进程不存在；结合输出时间戳，并在同一宿主权限下核对。恢复后台任务后已实测这一差异，重复启动必须先检查原 worker 的真实进程，不能覆盖其状态或全局终止求解器。
- 长解算默认 auto-save=0 会在非正常中断后只剩顶点输出，缺少可续跑速度／状态。已为通用入口启用每 120 输出帧保存及完成状态保存；不能从顶点序列伪造精确物理检查点。

- 官方 PPF 的 finished() 在保存检查点退出后也可能为真。包装器必须核对最后输出帧，不能把检查点当全片完成。
- 原生求解输出会重排顶点，读取完成前缀必须使用官方 CBOR 顶点映射，不能取前 N 点。前缀状态须明确，不能冒充完整结果。

- 原始发片已有静置自交，不能直接启用自碰后指望解算修复。用合法体积代理，显示点必须包含在四面体内；外推会在代理无穿插时穿皮肤。
- 逐帧可行姿态不等于连续自然动作。某候选几乎消除交线，却让峰值手速翻倍，已拒绝。使用共享时间样条，并独立记录源与修正速度。
- 顶点距离约束会漏掉面内部交叉。需要实际三角形见证；但无条件重复添加见证约束曾破坏原身体回归。仅在该对没有穿透顶点约束时补面内部约束。
- 平滑骨骼轨迹后仍可能是腕部 LBS 皮肤折叠。局部原生 DQ 混合可解决本例不到 1mm 的折叠；全局改 DQ 会改变头、身体和保护段，不能直接采用。少量代表帧可行的混合 0.75 在完整 225 样本中仍失败，最终用 1.0 并独立 1/32 帧重查。
- REST 碰撞拓扑构建时，已绑定的测量位置节点会覆盖静置蒙皮。临时暂停这些节点，成功及异常路径都恢复其原可见性及骨架姿态；新增契约测试。
- PPF 碰撞三角形有条件数下限。薄退化面不能简单删除；用规定动画包围盒保守覆盖，并检查原三角形包含。适配步骤须同时携带四面体绑定文件，不能只复制轨迹而丢失显示映射。
- 物理 CCD 只保护求解器对象；低频输出及显示映射仍能穿模。当前 120fps 输出、骨局部直接重心嵌入，再验真实显示网格；离散通过不证明显示 CCD。
- 扩大解算窗口时，物理休止体积原在旧起点，必须按旧头锚点搬运到新起点。不能直接把旧世界坐标体积放到新动画开头。
